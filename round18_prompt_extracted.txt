STEP 2 — Fix the root cause with a single-writer architecture

Implement exactly this structure, replacing the current mix of writers:

Four nested layers per desktop item, each owned by exactly one controller and never written by another:
.di-slot: base position from the layout engine only (CSS variables set from saved or computed grid cell; never from transformed rectangles).
.di-push: temporary displacement from the displacement controller (CSS variables --push-x, --push-y, applied with translate3d).
.di-drag: drag offset from the drag controller only while a drag is active.
.di-zoom: hover/selection scale from the hover controller.
Pure displacement. Compute displacement only from cached BASE rectangles (read from .di-slot before any transform, or from stored layout numbers), never from getBoundingClientRect() of an element that may be transformed. Recompute only when the state changes (expand, collapse, resize, side change), not every frame. Same inputs give the same outputs (idempotent), so cycles cannot accumulate drift.
One hover state machine for all folders: idle -> intent (60 ms) -> expanded(activeId) -> closing (280 ms grace) -> idle. Only one folder can be active. While expanded or closing, every other desktop item gets pointer-events: none so a displaced neighbour can never steal the pointer; the active folder, its pills, its connector and its bridge zone receive events. Moving back into the zone cancels closing. A click on the active folder only selects it (no collapse and re-expand, no side change). A drag start collapses the folder immediately and suspends displacement; after a drag ends no expansion starts until the pointer has left and re-entered.
Click versus drag. A press that moves less than 5 px and ends within 300 ms is a click: it changes only the selection. pointerup, pointercancel and lostpointercapture all clear the drag state; setPointerCapture is released; a click right after a drag is swallowed; right-click never starts a drag.
Expansion side comes from the configured side (Step 8), never from the icon's current position. Remove the "left half or right half" detection.
Delete the old displacement code (shiftY +56 / -50), duplicate hover timers, and any code that writes transform on the item element outside its own layer.
